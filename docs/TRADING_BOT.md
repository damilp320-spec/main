# Торговый бот Mythera — карта системы и план локальной работы

> Документ описывает **фактическое** состояние кода (не замысел) и пошаговый план
> запуска бота локально: от бумажного счёта до реальных денег.
> Всё проверено по исходникам `src/main/*`. Не является инвестиционной рекомендацией.

## 1. Из чего состоит бот (карта модулей)

| Модуль | Роль | Ключевое |
|---|---|---|
| `markets.js` | Слой данных | Свечи Yahoo Finance chart API + фолбэк Stooq (CSV, дневки). Кэш 20 с. `candles/search/trend/correlation/analyze`. Индикаторы SMA/EMA/RSI. Watchlist. |
| `backtest.js` | Движок стратегий | 8 стратегий, `signals()`, `simulate()`, метрики (return, buy&hold, maxDD, winRate, Sharpe, profit factor), `run()` c маркерами, `runBot()` (полная логика бота на истории), `optimize()` с walk-forward 70/30, `montecarlo()` (бутстрэп), `bestStrategy()`, `atr()`, `lastSignal()` |
| `tradingbot.js` | **Живой цикл** | Профили риска, конфиг (26 полей), `evaluate()`, управление позицией, сайзинг, автостоп, теневой режим, маршрут сигналов |
| `paper.js` | Бумажный счёт | Кэш/позиции/история, `trade()`, `valuation(quotes)`, кривая капитала (`snapshot/equityCurve/equityStats/benchmark`) |
| `trading.js` | Брокер (Tinkoff Invest REST) | sandbox/live, dry-run, подтверждение человеком, лимиты, белый список, «стоп-кран», аудит-лог, токен в `safeStorage` |
| `copilot.js` | ИИ-супервайзер («за рулём») | `consider()` — вердикт LLM по сигналу с контекстом (техника + новости + широта), предложения, `act()`, `monitor()` |
| `screener.js` | Скринер + широта рынка | 17 популярных тикеров + watchlist (до 24), фильтры RSI/тренд/пробой, breadth → risk-on/risk-off |
| `shadowlab.js` | Теневая лаборатория | Рейтинг ВСЕХ стратегий на одних данных, маркеры входов/выходов, форвард-тест с момента наблюдения |
| `dca.js` | Автопокупки | Усреднение по расписанию (тик раз в 5 мин), paper/broker |
| `alerts.js` | Алерты | price_above/below, rsi_above/below; фоновая проверка раз в 5 мин, авто-перевзвод, опционально → копилоту |
| `journal.js` | Журнал сделок | Ручные записи + авто-лог + импорт с бумаги + ИИ-разбор паттернов |
| `portfolio.js` | Портфельная аналитика | Распределение, концентрация (HHI), диверсификация, реализованный P&L, план ребаланса + применение |
| `news.js` / `analyst.js` | Контекст | Новости и сентимент; глубокий разбор актива |

**Фоновые таймеры** (`main.js`, запускаются при старте приложения):

| Что | Период | Условие |
|---|---|---|
| `tradingbot.evaluate()` | `intervalMin` (по умолч. 15 мин) | только если бот включён |
| `alerts.checkAll()` | 5 мин | всегда |
| `dca.tick()` | 5 мин | всегда |
| `copilot.monitor()` | `everyMin` (мин. 5, по умолч. 30) | только если копилот включён |
| Переоценка капитала | 5 мин | всегда |
| Дневной дайджест | проверка раз в час, отправка раз в день | по настройке |

## 2. Конвейер: данные → сигнал → риск → исполнение

```
Yahoo/Stooq ──► markets.candles (кэш 20с)
                      │
                      ├─► screener.breadth ──► фильтр режима рынка (risk-off → нет покупок)
                      ├─► news.sentiment ────► фильтр сентимента (< −20 → нет покупки)
                      ├─► markets.trend(старший ТФ) ─► MTF-подтверждение
                      │
                      ▼
            backtest.lastSignal(стратегия)
                      │
         ┌────────────┴─────────────┐
         │ signalRoute = 'direct'   │ signalRoute = 'ai'
         ▼                          ▼
   buy()/sell()              copilot.consider() ─► LLM-вердикт
         │                          │  (одобрено + уверенность ≥ порога)
         │                          ▼
         │                    предложение → человек подтверждает
         ▼
  mode='paper' ──► paper.trade() ──► journal.logAuto()
  mode='broker'──► trading.requestOrder() ──► [гейты] ──► подтверждение ──► биржа
```

## 3. Точный алгоритм одного прогона `evaluate()`

Это ядро. Порядок важен — именно он определяет поведение.

1. Читается конфиг. **Если `enabled=false` — выход.**
2. Если `regimeFilter` — один раз за прогон считается широта рынка. `risk-off` → покупки запрещены.
3. **Для каждого тикера** из `symbols`:
   1. Грузятся свечи (`interval`, `range`). **Нужно ≥ 30 свечей**, иначе тикер пропускается.
   2. `price` = закрытие последней свечи; кладётся в `quotes` (для оценки счёта).
   3. Если `shadowMode` — параллельно считается рейтинг всех стратегий на этих же свечах (бесплатно, без денег) и отправляется в UI.
   4. **Синхронизация с бумажной позицией**: если позиция есть, а бот «не знает» — состояние восстанавливается (`entry = средняя цена`); если позиции нет, а бот думает что есть — сбрасывается. Это защита от рассинхрона после перезапуска.
   5. **Если в позиции** — управление ею (до генерации новых сигналов):
      - обновляется `peak` (максимум с момента входа);
      - **лесенка TP1**: если `tp1Pct` задан и цена ≥ входа×(1+tp1%) → продаётся `tp1SellPct`% позиции, ставится флаг `tp1Done`, **прогон по тикеру завершается**;
      - считается выход `exit` по приоритету:
        1. **ручной тейк** (перетащенный на графике, `chartLevels[symbol].tp`),
        2. **ручной стоп** (`chartLevels[symbol].stop`),
        3. тейк-профит `takeProfitPct`,
        4. стоп-лосс: `percent` → вход×(1−sl%), `atr` → вход − `atrMult`×ATR(14),
        5. трейлинг: `percent` → пик×(1−trail%), `atr` → пик − `atrMult`×ATR(14),
        6. безубыток (если `breakeven` и `tp1Done` и цена ≤ входа);
      - при выходе: продажа, событие `exit`, сброс состояния, **очистка ручных уровней**.
   6. **Сигнал стратегии**: `pickStrategy()` (при `strategy='auto'` — лучшая по `Sharpe×2 + доходность/10 − просадка/10`, кэш 6 ч) → `lastSignal()`.
      > ⚠️ `lastSignal` смотрит **только 2 последние свечи**. На дневках сигнал появляется редко — это нормально, но бот выглядит «спящим».
   7. Если сигнала нет или он совпадает с текущим состоянием — тикер пропускается.
   8. **Сигнал `buy`**:
      - уже в позиции → пропуск;
      - `risk-off` → пропуск с событием `skip`;
      - `useSentiment` и сентимент < −20 → пропуск;
      - `confirmTf` задан и старший ТФ «вниз» → пропуск;
      - `signalRoute='ai'` и копилот включён → сигнал уходит **на оценку ИИ**, сделки нет; итог вердикта возвращается в лог бота;
      - иначе → `buy()` с объёмом `sizeQty()`.
   9. **Сигнал `sell`**: если в позиции — продажа.
4. Состояние сохраняется в `settings.bot._state` (переживает перезапуск).
5. **Автостоп (circuit breaker)**: только для `mode='paper'`. Считается просадка от исторического пика капитала; при превышении `maxDrawdownPct` бот **выключается** и шлёт уведомление.

## 4. Полный справочник настроек бота (`settings.bot`)

| Поле | По умолч. | Смысл |
|---|---|---|
| `enabled` | `false` | Главный выключатель; включение запускает таймер и **сразу первый прогон** |
| `mode` | `paper` | `paper` — бумажный счёт; `broker` — заявки через все гейты `trading.js` |
| `signalRoute` | `direct` | `direct` — бот торгует сам; `ai` — сигналы уходят ИИ-супервайзеру (сделки не будет без одобрения) |
| `symbols` | из watchlist | Список тикеров. Пусто → берётся watchlist |
| `strategy` | `macd` | Одна из 8, либо `auto` (автовыбор под тикер, кэш 6 ч) |
| `params` | `{}` | Параметры стратегии |
| `interval` / `range` | `1d` / `6mo` | ТФ свечей и глубина истории |
| `intervalMin` | `15` | Период опроса в минутах (мин. 1) |
| `qty` | `10` | Объём: **штук** в paper, **лотов** в broker |
| `sizeMode` | `fixed` | `risk` → объём считается от `riskAmount` и дистанции до стопа (ATR или %) |
| `riskAmount` | `200` | Риск на сделку в деньгах при `sizeMode='risk'` |
| `stopType` | `percent` | `percent` или `atr` |
| `stopLossPct` | `0` | Стоп в % от входа (при ATR — флаг включения) |
| `takeProfitPct` | `0` | Тейк в % от входа |
| `trailingPct` | `0` | Трейлинг в % от пика |
| `atrMult` | `2` | Множитель ATR(14) для стопа/трейлинга |
| `tp1Pct` / `tp1SellPct` | `0` / `50` | Первая цель и доля позиции для частичного выхода |
| `breakeven` | `false` | После TP1 стоп переносится в безубыток |
| `useSentiment` | `false` | Фильтр по новостному сентименту |
| `confirmTf` | `''` | Подтверждение старшим ТФ (`1d`/`1wk`) |
| `regimeFilter` | `false` | Покупки только при `risk-on` (широта рынка) |
| `shadowMode` | `false` | Параллельный рейтинг всех стратегий по наблюдаемым тикерам |
| `maxDrawdownPct` | `0` | Автостоп по просадке счёта (**только paper**) |
| `_state` | `{}` | Внутреннее состояние позиций (не трогать руками) |

**Профили** (кнопки в UI перезаписывают часть полей):

| Профиль | Стратегия | ТФ | Опрос | Стоп / Тейк / Трейл | MTF | Сентимент |
|---|---|---|---|---|---|---|
| Агрессивный | momentum(5, 4%) | 1h / 1mo | 10 мин | 5 / 10 / 4 % | — | нет |
| Умеренный | MACD(12,26,9) | 1d / 6mo | 30 мин | 8 / 20 / 8 % | 1wk | да |
| Долгосрочный | golden_cross(50,200) | 1d / 2y | 240 мин | 15 / 50 / 15 % | 1wk | да |

## 5. Стратегии и метрики

**Стратегии** (`backtest.STRATEGIES`): `sma_cross`, `ema_cross`, `macd`, `rsi`, `bollinger`, `momentum` (ROC), `breakout` (пробой канала), `golden_cross`.
Все — **только лонг** (шортов нет). Сигнал возникает на пересечении/пробое.

**Метрики бэктеста**: доходность, buy&hold, макс. просадка, число сделок, винрейт, Sharpe (по дневным доходностям кривой, ×√252), profit factor.

**Инструменты валидации**:
- `optimize({walkForward:true})` — перебор сетки (до 60 комбинаций) на 70% истории + проверка на невиданных 30% (**out-of-sample**);
- `montecarlo()` — бутстрэп последовательности сделок (200–5000 прогонов) → медиана, p5/p95, вероятность убытка, **риск разорения**, худшая просадка;
- `shadowlab.lab()` — рейтинг всех 8 стратегий на одном активе + форвард-тест с момента начала наблюдения.

## 6. Слои безопасности (что именно мешает потерять деньги)

1. **Бумажный счёт по умолчанию** (`mode='paper'`) — реальных денег нет вообще.
2. **Песочница брокера** (`env='sandbox'`) — по умолчанию.
3. **Dry-run** (`dryRun=true`) — по умолчанию: заявка логируется как «симуляция», на биржу не уходит.
4. **Подтверждение человеком** (`confirmEveryOrder=true`) — по умолчанию. Заявки от ИИ (`source='agent'`) требуют подтверждения **всегда**, без исключений.
5. **Жёсткие лимиты**: `maxOrderValue` (10 000), `maxDailyOrders` (10), белый список инструментов.
6. **Автостоп по просадке** (`maxDrawdownPct`) — выключает бота.
7. **«Стоп-кран»** (`panic()`) — отменяет активные заявки у брокера, выключает автоторговлю, чистит очередь подтверждений.
8. **Аудит-лог** всех заявок (500 последних) + журнал сделок.

## 7. ПЛАН ЛОКАЛЬНОГО ЗАПУСКА

Шесть этапов. **Переход на следующий — только по критериям.** Не перепрыгивать.

### Этап 0. Подготовка среды

- [ ] Windows 11, приложение собрано/запущено (`npm start`).
- [ ] Интернет доступен (Yahoo Finance) — проверить в «Рынках»: график AAPL строится, источник `Yahoo Finance`.
- [ ] **Для ИИ-частей** (копилот, разбор журнала, новостной сентимент): запущен Ollama + установлена модель. Без Ollama бот в режиме `direct` работает полностью, а режим `ai` не выдаёт вердиктов.
- [ ] В «⚡ Производительность» включить прогрев модели и keep-alive (иначе первый вердикт копилота ждёт холодной загрузки).

**Критерий перехода:** график строится, данные свежие.

### Этап 1. Бумажный счёт, ручная проверка

- [ ] «Торговля» → карточка «Бумажный счёт» → «Сбросить», задать стартовый капитал (например 100 000).
- [ ] Собрать watchlist из 5–10 ликвидных тикеров («Рынки» → ⭐).
- [ ] В карточке бота: `mode = Бумажный`, `signalRoute = ⚡ Бот торгует сам`, профиль «Умеренный».
- [ ] Нажать **«▶ Прогнать раз»** и прочитать лог: должны появиться строки вида `прогон N тикеров (macd, бот сам)…` и `✓ прогон завершён`.
- [ ] Проверить крайние случаи: пустой список тикеров → предупреждение; выключенный бот → предупреждение.

**Критерий перехода:** прогон проходит без ошибок, лог понятен.

### Этап 2. Калибровка стратегии (без денег)

Для **каждого** тикера из списка:

1. **Теневая лаборатория** («Рынки» → 🧬 Лаборатория): узнать, какая из 8 стратегий исторически ведёт по этому активу.
2. **Бэктест бота** (кнопка 🧪 в карточке бота) — прогоняет **полную логику** со стопами/лесенкой, а не только сигналы.
3. **Оптимизация с walk-forward** («Рынки» → 🔧 Оптимизировать + галочка Walk-forward): смотреть **только на out-of-sample** результат. Если OOS сильно хуже train — параметры переподогнаны, брать проще.
4. **Монте-Карло** (кнопка 🎲): оценить риск разорения и худшую просадку.

**Критерии приёмки стратегии (ориентир, не догма):**

| Метрика | Порог |
|---|---|
| Сделок в тесте | ≥ 20 (иначе статистика не значима) |
| Sharpe (OOS) | ≥ 0.8 |
| Profit factor | ≥ 1.3 |
| Макс. просадка | ≤ вашей терпимости (обычно ≤ 20%) |
| OOS vs train | падение доходности не более чем в 2 раза |
| Риск разорения (МК) | ≤ 5% |
| Против buy&hold | не хуже, иначе проще купить и держать |

**Критерий перехода:** есть связка «тикер + стратегия + параметры», прошедшая пороги.

### Этап 3. Форвард-тест на бумаге (главный этап)

- [ ] Задать стопы: начать с профиля, затем подстроить (`stopType='atr'`, `atrMult=2` — адаптивнее процента).
- [ ] Включить `sizeMode='risk'`, `riskAmount` = 0.5–1% капитала на сделку.
- [ ] Включить `maxDrawdownPct` (например 15) — автостоп.
- [ ] Включить `regimeFilter` (не покупать в risk-off) и `confirmTf='1wk'`.
- [ ] Включить бота. `intervalMin`: дневки → 30–60 мин (чаще смысла нет, свеча не меняется).
- [ ] Включить уведомления в Telegram/Discord («Подключения») — чтобы видеть сделки не сидя в приложении.

**Что мониторить ежедневно:**
- **Кокпит** — капитал, P&L, состояние бота, широта рынка;
- **Кривая капитала** (вкладка «Торговля») — просадка, R:R, сравнение с S&P (альфа);
- **Журнал сделок** → «🤖 Разбор» — ИИ ищет паттерны и типичные ошибки;
- **Активность** — что именно делал бот (каждый вызов инструмента логируется);
- **Аналитика** — задержки, ошибки.

**Критерий перехода:** **минимум 4–8 недель** и **≥ 30 сделок** на бумаге, метрики держатся в рамках Этапа 2, нет сюрпризов в логах.

### Этап 4. Брокер: песочница + dry-run

- [ ] «Торговля» → «Подключение»: `env = 🟢 Песочница`, вставить токен Tinkoff Invest (хранится зашифрованным), «Проверить» → выбрать счёт.
- [ ] Убедиться, что **включены**: `Симуляция (dry-run)` ✅, `Подтверждать каждую заявку` ✅, `Автоторговля` ❌.
- [ ] Заполнить **белый список** тикеров, выставить `maxOrderValue` и `maxDailyOrders` минимальными.
- [ ] Переключить бота в `mode='broker'` и наблюдать: заявки должны **логироваться как симуляция** и/или ждать подтверждения.
- [ ] Проверить «🛑 Стоп-кран».

**Критерий перехода:** 2+ недели, заявки формируются корректно, лимиты срабатывают, стоп-кран работает.

### Этап 5. Песочница без dry-run

- [ ] Выключить `dryRun` (останется песочница + подтверждение). Заявки реально уходят в sandbox-счёт.
- [ ] Сверить исполнение с ожиданиями (цены, лоты, проскальзывание).

**Критерий перехода:** исполнение совпадает с ожиданиями.

### Этап 6. Live — минимальными шагами

> ⚠️ Реальные деньги. Каждый шаг — отдельно, с паузой в неделю.

- [ ] `env = 🔴 Live` (приложение потребует подтверждение).
- [ ] **Оставить** `confirmEveryOrder=true` — вы подтверждаете каждую заявку руками.
- [ ] `maxOrderValue` = минимум (1–2% депозита), `maxDailyOrders` = 2–3, белый список обязателен.
- [ ] Неделя ручных подтверждений → только потом рассматривать снятие `confirmEveryOrder`.
- [ ] Автоторговлю без подтверждений включать **в последнюю очередь** и только с жёсткими лимитами.

## 8. Эксплуатация

**Расписание.** Бот не знает про часы работы биржи и опрашивает данные круглосуточно. Для дневных стратегий это безвредно (свеча не меняется), но лишний трафик. Рекомендация: `intervalMin` ≥ 30 для `1d`, ≥ 10 для `1h`.

**Аварийные процедуры:**

| Ситуация | Действие |
|---|---|
| Нужно всё остановить | «🛑 Стоп-кран» в «Торговле» + выключить бота |
| Бот «сошёл с ума» | Выключить `enabled`; проверить `_state` через сброс конфига |
| Сработал автостоп | Бот уже выключен сам; разобрать причину в журнале и кривой капитала |
| Позиция «залипла» | Закрыть вручную с графика («Рынки» → ✖ Закрыть позицию), уровни сбросятся |
| Стоп не там | Перетащить линию стопа/тейка на графике — бот соблюдает ручные уровни приоритетно |
| Данные устарели/битые | Проверить источник в шапке графика (Yahoo/Stooq); при фолбэке на Stooq доступны только дневки |

## 9. Найденные дефекты и ограничения (честно)

Это реальные находки по коду — их стоит починить до реальных денег.

| № | Проблема | Где | Риск |
|---|---|---|---|
| 1 | **В брокерском режиме игнорируется риск-сайзинг**: `brokerOrder` всегда шлёт `lots: c.qty`, результат `sizeQty()` не используется | `tradingbot.js` → `brokerOrder` | Объём не соответствует риску |
| 2 | **Частичный выход у брокера продаёт всё**: `sellPartial` в режиме broker вызывает обычный `brokerOrder(..., 'sell')` на `c.qty` лотов | `tradingbot.js` → `sellPartial` | Лесенка TP не работает у брокера |
| 3 | **Продажа у брокера не привязана к размеру позиции** — тоже `c.qty` лотов | `tradingbot.js` → `sell` | Недо-/переп��одажа |
| 4 | **`maxDailyLossPct` нигде не проверяется** — в `requestOrder` есть только белый список, `maxOrderValue`, `maxDailyOrders` | `trading.js` | Дневной лимит убытка не работает |
| 5 | **Автостоп по просадке только для paper** | `tradingbot.js` | В broker-режиме защиты нет |
| 6 | **В бэктесте нет комиссий и проскальзывания** | `backtest.js` | Результаты систематически оптимистичны |
| 7 | **Исполнение по цене закрытия свечи**, без спреда | `backtest.js`, `paper.js` | Оптимизм на неликвиде/интрадее |
| 8 | **`lastSignal` смотрит только 2 последние свечи** | `backtest.js` | Сигналы редки; пропуск при простое бота |
| 9 | **Нет учёта часов торгов и выходных** | `tradingbot.js` | Лишние прогоны, сигналы по «старой» свече |
| 10 | **Только лонг**, шортов нет | `backtest.js` | Нет заработка на падении |
| 11 | **Нет лимита числа одновременных позиций** и экспозиции на тикер | `tradingbot.js` | Возможна концентрация риска |
| 12 | **Источник данных неофициальный** (Yahoo), может измениться/забаниться | `markets.js` | Остановка данных; фолбэк только дневной |
| 13 | **`report()` всегда пишет «(бумажный)»** | `tradingbot.js` | Путаница в уведомлениях у брокера |

## 10. Дорожная карта: как сделать бота «более проработанным»

Приоритет сверху вниз — сначала то, что защищает деньги.

**P0 — до реальных денег (обязательно)**
1. Починить п.1–3: брокерские заявки должны использовать `sizeQty()`, продажа — фактический размер позиции, частичный выход — долю.
2. Реализовать `maxDailyLossPct` в `requestOrder` (считать реализованный P&L за день, блокировать заявки при превышении).
3. Распространить автостоп по просадке на брокерский режим (по данным портфеля).
4. Добавить в бэктест **комиссию и проскальзывание** (параметры в настройках) — иначе калибровка врёт.

**P1 — качество сигналов и риска**
5. Учёт часов торгов/выходных: не торговать вне сессии, не реагировать на «протухшую» свечу; kill-switch при устаревании данных.
6. Лимиты портфеля: максимум одновременных позиций, максимальная доля на тикер, учёт корреляций (`markets.correlation`) при наборе позиций.
7. Временной выход (max holding period) и выход по «затуханию» сигнала.
8. Блэкаут вокруг отчётностей/крупных новостей.

**P2 — исследование и адаптация**
9. Регулярная переоптимизация по расписанию (walk-forward «катящимся окном») с автоприменением только при прохождении порогов.
10. Режимо-зависимые параметры: разные наборы для risk-on/risk-off.
11. Портфельный Монте-Карло (не по одному тикеру, а по всей корзине).
12. Шорты и/или инверсные инструменты.

**P3 — эксплуатация**
13. Резервный источник данных и ретраи с бэкоффом.
14. Метрики бота в «Аналитику»: сигналов/сделок в неделю, доля пропусков по фильтрам, латентность.
15. Расширенный аудит: почему сделка НЕ состоялась (сейчас частично есть через события `skip`).
